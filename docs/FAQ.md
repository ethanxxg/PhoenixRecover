# PhoenixRecover 常见问题 (FAQ)

---

### Q1: 扫描需要多长时间？

扫描时间取决于磁盘容量、接口速度和文件数量。一般参考：

| 磁盘容量 | 预计时间（USB 3.0 机械硬盘） |
|----------|------------------------------|
| 32 GB U 盘 | 2–5 分钟 |
| 256 GB SSD | 5–15 分钟 |
| 1 TB 机械硬盘 | 20–60 分钟 |
| 4 TB 机械硬盘 | 1–3 小时 |

三阶段扫描中，阶段 1（元数据解析）最快，阶段 3（签名雕刻）需逐扇区扫描，耗时最长。扫描过程支持随时取消。

---

### Q2: 恢复的文件能保证完整吗？

不能保证 100% 完整。文件恢复成功率取决于多个因素：

- **文件系统元数据是否完好**：如果文件系统结构未被覆盖，恢复成功率最高。
- **数据区域是否已被覆盖**：如果文件数据所在的扇区已被新数据写入，则无法恢复。
- **文件碎片化程度**：高度碎片化的文件在签名雕刻阶段可能只能部分恢复。

程序会以颜色标识每个文件的可恢复性等级：绿色（正常）> 橙色（已重建）> 红色（已删除），供您参考判断。

---

### Q3: 为什么不能恢复到源磁盘？

将文件恢复到源磁盘会**写入新数据**，可能覆盖尚未恢复的其他文件。PhoenixRecover 内置同卷写保护机制，会在恢复前自动检测并阻止向源磁盘写入。

**建议**：将文件恢复到另一块磁盘、U 盘或网络共享目录。

---

### Q4: 支持哪些文件系统？

当前支持以下文件系统的元数据解析：

| 文件系统 | 支持状态 |
|----------|----------|
| NTFS | ✅ 完整支持（含 MFT 解析、USN Journal） |
| FAT12 / FAT16 / FAT32 | ✅ 完整支持 |
| exFAT | ✅ 完整支持 |
| ext4 | ✅ 基础支持 |

即使文件系统不被直接支持，签名雕刻阶段仍可通过文件头特征匹配发现文件。

---

### Q5: 如何添加自定义文件签名？

1. 创建一个 JSON 文件，按照 `docs/SIGNATURE_FORMAT.md` 定义的格式编写签名。
2. 在程序中加载该 JSON 文件。

**示例签名文件片段：**

```json
{
  "signatures": [
    {
      "extension": "sqlite",
      "description": "SQLite 3 Database",
      "magic": "53514C69746520666F726D6174203300",
      "offset": 0,
      "maxFileSize": 104857600
    }
  ]
}
```

参考 `testdata/custom_signatures.json` 获取完整示例。

### Q6: Linux / macOS 是否支持？

当前状态：

- **Windows**：完整支持，主要开发和测试平台。
- **Linux**：实验性支持。磁盘/分区访问模块已完成平台拆分（POSIX API），但尚未在多种发行版上完整验证。
- **macOS**：实验性支持。基础 I/O 层已实现，功能验证尚不充分。

在 Linux/macOS 上可通过 `-DPHOENIX_BUILD_GUI=OFF` 构建仅测试版本。

---

### Q7: 扫描过程中可以取消吗？

可以。扫描过程中随时点击「取消」按钮即可中止。取消操作会在当前扇区读取完成后安全停止，不会损坏源磁盘上的数据。已发现的文件仍然保留在结果列表中，可以正常恢复。

---

### Q8: 程序是否会修改源磁盘上的数据？

**不会**。PhoenixRecover 以只读方式访问源磁盘，仅在恢复文件时向目标磁盘写入数据。扫描、预览、镜像等操作均不会修改源磁盘内容。

---

### Q9: 恢复的文件名为什么是乱码或随机名称？

可能的原因：

- **文件系统元数据已损坏**：目录项被覆盖后，文件名信息丢失。此时程序会根据文件签名生成临时名称（如 `carved_00001.jpg`）。
- **编码问题**：部分老旧文件系统使用非 Unicode 编码，可能在显示时出现乱码。

通过签名雕刻阶段发现的文件通常无法恢复原始文件名，但文件内容可能仍然完好。

---

### Q10: 可以恢复格式化后的磁盘吗？

取决于格式化类型：

- **快速格式化**：仅清除文件系统元数据，数据区域通常未被覆盖，恢复成功率较高。
- **完整格式化**：Windows 7 及以上版本的完整格式化会对全盘写零，此时数据已被覆盖，无法恢复。

建议在发现误格式化后**立即停止使用该磁盘**，避免新数据写入覆盖待恢复内容。

---

### Q11: 能恢复 SSD 上删除的文件吗？

SSD 恢复成功率通常低于机械硬盘。原因是 SSD 固件会自动执行 TRIM 指令，在后台擦除已删除文件占用的闪存块。一旦 TRIM 执行完成，数据将无法恢复。

**建议**：发现数据丢失后尽快断开 SSD 电源，减少 TRIM 执行窗口。

---

### Q12: 程序崩溃或意外退出后，扫描结果还在吗？

PhoenixRecover 在扫描完成后会自动保存会话。如果扫描已完成，下次启动时可加载上次的扫描结果。但如果程序在扫描过程中崩溃，未完成的扫描结果不会被保存，需要重新扫描。
